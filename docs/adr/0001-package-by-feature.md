# ADR 0001: Package-by-feature 아키텍처

날짜: 2026-08-28 · 상태: 채택

## 배경

이 템플릿에는 기능이 늘어나도 구조가 유지되고, AI 에이전트가 레퍼런스 구현을 패턴 삼아 확장할 수 있는 구조가 필요하다. 후보: 전역 계층형(controller/service/repository), 헥사고날(포트 & 어댑터), package-by-feature.

## 결정

Package-by-feature를 채택한다. 각 기능은 하나의 패키지(`com.example.skeleton.<feature>`)에 컨트롤러, 서비스, 리포지토리 인터페이스 + 구현, 도메인 모델, DTO, 예외를 모두 담는다. 횡단 관심사는 `common`에 두며, `common`은 절대 기능 패키지에 의존할 수 없다. 기능 패키지끼리도 서로 의존할 수 없다.

이 규칙은 관례가 아니라 ArchUnit 테스트(`ArchitectureTest`)로 강제한다.

## 결과

- 한 기능의 모든 컨텍스트가 한 디렉터리에 모여 있어 사람과 에이전트 모두 탐색 비용이 낮다.
- package-private 가시성이 실질적 의미를 가진다(컨트롤러와 리포지토리 구현체를 숨길 수 있다).
- 기능 간 재사용은 `common`을 거치거나 명시적인 새 결정을 요구하므로 우발적 결합이 차단된다.
- 헥사고날보다 형식적 부담이 적다. 도메인 로직이 복잡해지면 새 ADR로 재검토한다.
