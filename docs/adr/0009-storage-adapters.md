# ADR 0009: 영속성 도입 — JPA 단일 어댑터, 인메모리는 테스트 픽스처로

날짜: 2026-09-07 · 상태: 채택 (ADR 0002를 대체)

## 배경

ADR 0002는 영속성 기술 선택을 미루고 인메모리 구현만 두기로 했다. 아키텍처 확정(기능형 + 포트 역전,
ADR 0008) 이후 영속성을 도입한다. 도입 과정에서 인메모리/JPA/MyBatis 3종 어댑터 + 프로퍼티 선택
스위치를 실험적으로 구현해 포트 계약 테스트까지 전부 통과시켰으나, **쓰지 않을 기술의 유지비**(의존성,
설정, 어댑터 코드)를 이유로 단일화했다 — 포트-어댑터 구조 덕에 "여러 구현이 가능함"은 이미 증명됐고,
증명을 위해 구현을 상비할 필요는 없다.

## 결정

- **프로덕션 구현은 JPA 어댑터 하나다.** `storage/` 직하에 3형제를 둔다:
  `OrderEntity`(@Entity, JPA 요구사항 전담) + `OrderJpaRepository`(Spring Data, 어댑터 내부 부품) +
  `JpaOrderRepositoryAdapter`(포트 구현, 도메인↔엔티티 번역). 기술이 하나이므로 ADR 0008의 기준대로
  `storage/jpa/` 같은 기술별 하위 분할은 하지 않는다 (두 번째 기술이 오면 그때 나눈다).
- **DB는 H2 인메모리** (Docker 불필요). 실 DB(PostgreSQL 등) 전환 시 드라이버·datasource 교체 +
  Testcontainers 계약 테스트가 작업 범위이며, 그때 Flyway 도입을 함께 결정한다.
- **스키마의 단일 원본은 `schema.sql`** — Hibernate `ddl-auto=none`으로 DDL 생성을 금지한다.
- `@Entity`는 storage의 사유물이다. 도메인 `Order`(record)는 애노테이션 무균을 유지한다.
- **`InMemoryOrderRepository`는 `src/test`의 테스트 픽스처로 강등** — 서비스/슬라이스 테스트가 mock 없이
  실제 리포지토리 동작으로 돌게 해주는 용도로만 존재한다.

## 검증

**포트 계약 테스트**(`OrderRepositoryContractTest`)가 라운드트립·업서트·정렬·삭제 계약을 정의하고,
구현별 서브클래스가 `repository()` 하나만 제공해 동일 계약을 상속받는다. 현재 서브클래스는 둘:
프로덕션 JPA 어댑터(H2, `@SpringBootTest`)와 테스트 픽스처(순수 단위) — **픽스처가 계약을 어기면 그
위의 모든 테스트가 거짓이 되므로 픽스처도 같은 게이트를 통과해야 한다.** 새 어댑터 추가 시 서브클래스
하나로 같은 계약이 적용된다.

## 결과

- 이 도입에서 application/domain/api는 한 글자도 바뀌지 않았다 — ADR 0002가 약속했던 "storage 안의
  교체극"이 실증됐다 (MyBatis 어댑터도 동일 계약을 통과했던 것이 그 증거이며, 커밋 전 제거됐다).
- 통합 테스트(주문 라이프사이클 등)는 이제 실제 JPA + H2 위에서 돈다.
