# ADR 0002: 데이터베이스 없음 — 리포지토리는 인터페이스 + 인메모리 구현

날짜: 2026-08-28 · 상태: **대체됨 → [ADR 0009](0009-storage-adapters.md)** (2026-09-07 영속성 도입)

## 배경

이 템플릿은 API 계층의 베스트 프랙티스를 보여주는 것이 목적이며, 영속성 기술 선택(JPA vs JDBC vs NoSQL)이나 로컬 Docker 의존을 템플릿 사용자에게 강제하지 않아야 한다.

## 결정

각 기능은 리포지토리 인터페이스(예: `OrderRepository`)를 정의하고, `ConcurrentHashMap` 기반의 package-private 인메모리 구현을 함께 둔다. 서비스와 컨트롤러는 인터페이스에만 의존한다.

## 결과

- 서비스 테스트가 실제 리포지토리 구현을 상대로 돌아가므로 모킹 프레임워크가 필요 없다.
- 나중에 실제 데이터베이스를 붙일 때는 인터페이스 구현체(예: `JpaOrderRepository`)를 추가하고 인메모리 빈을 제거하면 된다. 서비스와 컨트롤러는 변경되지 않는다.
- 데이터는 재시작 시 사라진다. 이는 템플릿의 속성이지 운영 환경의 자세가 아니다.
- 데이터베이스 도입 시 Testcontainers 기반 통합 테스트를 추가하고 새 ADR을 작성한다.
